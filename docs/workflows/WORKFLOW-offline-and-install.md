# Workflow: installation, offline help and optional typed drafts

2026-11-01. Owner authorized remaining roadmap work. Implements G14/G19; browser installation support varies by browser. Source research: [MDN installation](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), [MDN install prompt](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event), [web.dev assets and data](https://web.dev/learn/pwa/assets-and-data).

Actors: shop owner, browser, service worker, authenticated API. The app remains network-dependent for private ledger reads and confirmed writes. No background sync or queued money/message writes are introduced.

1. Online visit registers `/sw.js` in production. Installation atomically caches only `/offline.html` and three public icons. If registration fails, the live app remains usable. Manifest declares standalone display and actual 192/512/maskable PNGs. Browser install prompt is shown only when the browser emits its support event; browser menu instructions remain in the getting-started guide.
2. Worker intercepts only same-origin GETs. APIs, non-GETs and RSC bypass it. Authenticated/private document navigation is fetched from network and never written to CacheStorage. A failed navigation returns static bilingual offline help, never a private snapshot. Activation deletes older app-owned shell caches, not other applications' caches.
3. A mounted typed editor shows network loss and disables submission. Reconnection prompts a record refresh and never repeats an earlier request. Offline help says an unanswered write may have completed and requires checking ledger/message history before retrying.
4. Optional draft saving requires explicit checkbox consent and Save draft. Only up to 400 typed characters are saved in sessionStorage in the current browser tab; no audio, ledger rows or automatic sends. The helper expires data after 24 hours, and a draft with another account/session namespace is deleted rather than shown. Anonymous real-shop users cannot get a draft namespace. Namespace is an opaque server HMAC scoped to shop and session version.
5. Reload does not fill or submit a saved draft. The owner must press Restore draft for review, revalidate the account online, then generate a fresh proposal and confirm it through the normal ledger flow. Delete saved draft removes saved local text. Auth transitions clear local drafts centrally and broadcast a non-sensitive clear signal to other open tabs. Editors recheck their account scope on focus and before restoration. Disabled storage shows an error without breaking the editor. A saved draft may contain a customer name; shared-device guidance and tab lifetime are explicit.
6. `/shop/start` derives checklist status from current APIs (customer count, confirmed entries, counted products, configured UPI). Failures show unknown progress and retry. Checklist is skippable, and readiness never asserts payment settlement or UPI ownership.

Failure boundaries: private data is not available in the offline cache; browser network state is a hint, not a proof of server reachability. Existing 30-second client deadlines and uncertain-write hints still apply if the network fails without an offline event. No automated/manual screen-reader or physical install test is claimed; automated browser checks cover restoration, no offline submission, static cache allowlist, offline fallback and serious/critical accessibility on the guide.
